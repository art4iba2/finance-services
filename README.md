# Gateway и Ledger

Два независимых Go-модуля в одном Git-репозитории. Внешние зависимости отсутствуют. Требуется Go 1.22 или новее.

```text
gateway/
  go.mod
  main.go
  main_test.go
ledger/
  go.mod
  main.go
  internal/ledger/
    transaction.go
    transaction_test.go
```

## Запуск Gateway

Из корня репозитория в первом терминале:

```bash
cd gateway
go run .
```

Сервер слушает порт 8080. Во втором терминале:

```bash
curl -i http://localhost:8080/ping
```

Ожидаемый статус — `200 OK`, тело — ровно `pong`. Для других HTTP-методов на `/ping` возвращается `405 Method Not Allowed` с заголовком `Allow: GET`; для неизвестного пути — `404 Not Found`. Остановить сервер можно сочетанием Ctrl+C.

## Запуск Ledger

Из корня репозитория в отдельном терминале:

```bash
cd ledger
go run .
```

Ожидаемый вывод:

```text
Ledger service started
ID=1 | Amount=1250.50 | Category=Продукты | Description=Покупка продуктов | Date=2026-10-01
ID=2 | Amount=350.00 | Category=Транспорт | Description=Поездка на такси | Date=2026-10-02
ID=3 | Amount=890.00 | Category=Развлечения | Description=Билет в кино | Date=2026-10-03
```

После вывода Ledger завершает работу: сервер пока не требуется. При каждом запуске хранилище создаётся заново; данные не сохраняются на диск.

## Хранилище транзакций

Бизнес-логика находится в пакете `ledger/internal/ledger`:

- `Transaction`: `ID int`, `Amount float64`, `Category string`, `Description string`, `Date time.Time`.
- `AddTransaction(tx Transaction) error`: отклоняет нулевую сумму, присваивает последовательный ID, добавляет транзакцию и возвращает `nil`. Переданный ID заменяется автоматически. Отклонённая транзакция не занимает ID.
- `ListTransactions() []Transaction`: возвращает копию среза в порядке добавления.

Отрицательные суммы допускаются (например, для возвратов). Использование `float64` соответствует учебному заданию; в дальнейшем для точных денежных расчётов можно перейти на целое число копеек. Хранилище рассчитано на последовательные вызовы из `main`; перед добавлением конкурентного gRPC-сервера потребуется синхронизация.

## Проверки

Запустите команды из корня репозитория:

```bash
(cd gateway && go test ./... && go vet ./...)
(cd ledger && go test ./... && go vet ./...)
```

Тесты проверяют `/ping`, ограничение метода, пустое хранилище, сохранение полей, автоинкремент ID, отказ при нулевой сумме и независимость возвращаемой копии.

## Git и удалённый репозиторий

В архив включён локальный Git-репозиторий с коммитом реализации. Удалённый репозиторий не настроен, поскольку его URL не был предоставлен. После распаковки можно привязать свой репозиторий и отправить коммит:

```bash
git remote add origin <URL-вашего-репозитория>
git push -u origin main
```

Если удалённый репозиторий уже содержит коммиты, сначала согласуйте историю; приведённые команды предназначены для пустого удалённого репозитория.
